NGS or HTS?

  • NGS — Next Generation Sequencing
  • HTS — High Throughput Sequencing

Two names for the same machines. "Next generation" was next about twenty years ago; papers that still use it mean nothing more than not Sanger. HTS is the term that ages better.

Same instruments, same files. Read either word as "not Sanger".

How to assemble? (short reads)

1. Mapping / Alignment — put every read where it belongs on a sequence you already have
2. De novo assembly — build the sequence out of the reads themselves
The first question is always the same: do I already have a reference, or do I have to make one?

Mapping / Alignment

  • Align short reads onto a reference sequence
    • Reference sequence is necessary

De novo assembly

  • Join reads into longer sequences — contigs, then scaffolds
  • Mis-assembly happens: a repeat longer than the read collapses into a single copy, and nothing in the output says so
A read shorter than the repeat cannot tell two copies apart. That, and not cost, is why long reads exist.

What is DNA-seq?

Shear the genome, sequence a few million fragments, put them back. What you get is coverage — how many times each position was read. A variant, a contig, a copy number are all inferences drawn from it.

DNA→fragmentation→library→reads→coverage→assembly or variants

How deep is a decision, not a property of the sample. Variant calling and de novo assembly want very different depths.
Nothing separates a sequencing error from a rare real variant except how often you see it.
Same instrument, same FASTQ file. What differs is what you ask the coverage to tell you.

“The complete sequence” is the goal, not the result: GRCh38 carried about 8 % of the human genome as N for a decade.

Trimming is not free. Every read you filter is a read you paid for, and shorter reads move the mapping rate — and therefore the counts.
QC does not stop at the FASTQ. Mapping rate, duplicate rate and the count matrix are QC too, and they catch what FastQC cannot.
FastQC never changes a file. It only tells you what is in one. Trimming is a separate tool, and a separate decision that is yours.

Accuracy is as the vendors state it: PacBio gives median HiFi read quality ≥Q30 with 90 % of bases Q30+ (pacb.com/revio); Oxford Nanopore gives Q20+ simplex — 99.0 to 99.6 % modal depending on run speed — and ≈Q30 duplex for R10.4.1 + Kit 14 (nanoporetech.com); Illumina defines Q30 as one error in 1,000 bases. FASTQ format

@SEQ_ID GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCCATTTGTTCAACTC + !''*((((***+))%%%++)(%%%%).1***-+*''))**55CCF>>>>>>CC
Line What it is
1 @ and then the identifier instrument, run, lane, tile, coordinates
2 the sequence A C G T, and N where the machine gave up
3 + a separator; older files repeated line 1 after it
4 the quality one character per base of line 2
Line 4 is exactly as long as line 2. When it is not, the file is truncated — check that before anything else.

"Phred quality scores Q are defined as a property which is logarithmically related to the base-calling error probabilities." (Wikipedia)

The quality line carries one character per base. A number such as 30 does not fit in one character, so it is shifted by 33 and written as ASCII.

character = chr(Quality + 33)

Why 33? Because ASCII 0–31 are control characters and 32 is the space — none of them can sit safely in a line of a text file.

e.g. Phred quality score=30 → ???

'?'

Phred quality score

  • Illumina 1.8+ — Sanger encoding, Phred+33
  • Scores 0–41, offset 33
  • Illumina 1.3–1.7 used Phred+64: the same scores, written with different characters
If every base in an old file looks about 31 points better than it should, suspect the offset before you praise the sequencer.
